# Code audit, October 2026

An audit of Madeira's own code at upstream commit `48f9764`, done on the
`windows-d3d12-build` branch of the fork. It covers about 220,000 lines:
`app/`, `build/` (the iOS ports of Wine's ntdll, win32u and wineserver, madsync,
media, crypto), `madeira-d3d12/`, the build scripts and `tests/host`.

The submodule forks (FEX, Wine, DXMT, Madeira Dock) were **not** audited. Only
Madeira's changes to them would be worth reviewing, and that needs their
upstream merge bases checked out.

## Method

Ten reviewers each read one area for correctness, memory-safety, concurrency,
security and compatibility defects, ignoring style. Every finding marked
**fixed** below was then checked against the code by hand before it was changed.
Findings in the backlog are the reviewers' reports and are **not yet verified**
unless they say so. One reported finding was disproved; see
[Rejected findings](#rejected-findings).

Build status of the fixes:

- **madeira-d3d12 PE side:** compiled with `build/madeira-d3d12/build-pe-windows.sh`.
- **Winios input ring:** unit-tested on the host by extracting the real code.
- **Everything else:** written on a Windows host, so not compiled. It needs a
  macOS build, which no CI yet provides.

## Overall assessment

- **Line-level care is generally good:** buffers are bounded, sizes checked,
  and hashes pinned where it matters.
- **The weak spots are where iOS breaks Wine's process model:**
  - one process and one Mach exception thread for every pseudo-process;
  - a shared cwd, environment and stdio;
  - 16 KB host pages under 4 KB guest pages;
  - JIT aliases;
  - lifetime and teardown of per-thread and per-session state.
- **madeira-d3d12** is defensive about bounds. Its gaps are object lifetime,
  caches shared across queues, and D3D12 semantics not implemented yet: count
  buffers, RTV formats, query delivery.
- **The Swift app** keeps credentials in the Keychain, and path sanitising is
  sound. Its risks are state machines that can wedge, and lifecycle gaps in
  installs and updates.
- **The build chain cannot be reproduced from a clean clone.** Several inputs
  are produced by no script (see [Build and CI](#build-and-ci)).

## Rejected findings

- **`audio_null_ios.c` `is_format_supported_params` "missing `fmt_out`"**: the
  reviewer used an older Wine layout. Madeira's Wine fork at `257f271`
  (`dlls/mmdevapi/unixlib.h`) has no `fmt_out`, so the iOS struct matches.

## Backlog (not fixed)

Ordered by likely impact. **[V]** marks findings verified while working on a
neighbouring fix; the rest are as reported. "Fast loop" means a PE-only
madeira-d3d12 change that can be tested as a drop-in `d3d12.dll`.

### Crash, hang or corruption

1. **d3d12, device lifetime** (`madeira_d3d12.c` `device_Release`, child
   constructors): children never AddRef the device. Releasing the device before
   its queues, resources or swapchain is a common shutdown order, and children
   then use freed device state. *Fix:* AddRef in each child constructor and
   Release in its destructor. Fast loop.
2. **d3d12, queue teardown race** (`mad_device_flush_all` vs `queue_Release`):
   a dying queue can be revived and destroyed twice. *Fix:* unregister first;
   take a reference with a CAS only while refs > 0. Fast loop.
3. **virtual, JIT aliases outlive MEM_RELEASE** (`delete_view`, `free_pages`):
   a later allocation at the same address inherits the stale RX alias, which
   affects Mono, .NET and LuaJIT. *Fix:* tombstone the aliases and free the pool
   slot on release.
4. **virtual, decommit memset can fault under `virtual_mutex`**
   (`decommit_pages` edge and sub-page zeroing on non-writable host pages). The
   fault handler then blocks on the same mutex and the app hangs.
5. **signal, Wine log macros on the Mach exception thread** (`ios_lookup_thread`
   `[reg-miss]`, `[x18-*]`, CAS `ERR`s): the thread has no TEB, so its own fault
   parks every later fault. *Fix:* use `dprintf` on those paths.
6. **signal, thread registry is append-only (512 entries)**: threads after the
   512th are unregistered and get slot 0's TEB and PEB. *Fix:* clear the entry at
   thread exit and reuse it.
7. **signal, unsafe instruction fetch in `segv_handler`/`bus_handler`**: an
   execute fault at an unmapped PC refaults inside the handler and kills the
   whole app. *Fix:* use `ios_fault_read_insn`.
8. **signal, store emulators:**
   - `bus_handler` drops pre/post-index writeback;
   - Mach-path `LDUR Q` results are lost;
   - CAS/CASP run real atomics on misaligned addresses;
   - older case-4 branches use the fault address as the effective address.
9. **wineserver, madsync waiters are never aborted when their thread is
   killed**: zombie threads hold or take objects meant for live threads.
   *Fix:* `madsync_abort_owner(tid)` from `kill_thread`.
10. **wineserver, `open_fd` `fchdir`s the shared cwd**: this races other
    threads, and the cwd is left inside `.wineserver`. *Fix:* use the `*at()`
    calls on `root_fd`.
11. **wineserver, `fprintf(stderr)` while a thread is frozen** (`mach_ios.c`):
    the server hangs if that thread holds the stderr lock. Real suspend
    combined with madsync can also wedge the server on `g_lock`.
12. **audio, Reset races the render callback** (`audio_null_ios.c` reset):
    padding underflows, so the stream is silent for good after Stop then Reset.
    *Fix:* refuse Reset while started, then wait two `cb_epoch` passes.
13. **audio, no recovery when the RemoteIO unit stops** (interruptions, start
    failure): games gated on the audio clock hang.
14. **app, process environment changed while guest threads run** (`unsetenv`
    at teardown, `setenv("MADEIRA_DETACHED")`, the server thread setting
    `HOME`): this races `env_ios.c` walking `environ`.
15. **app, `get_win_data` global** (`IOSDisplayShim.m`): swapchains created
    concurrently can bind the wrong window's `CAMetalLayer`.
16. **d3d12 unix, shader-cache temp file shared by all threads**
    (`<key>.tmp<pid>`): concurrent stores of one key can publish a zero-filled
    entry. *Fix:* a unique temp name opened with `O_EXCL`.

### Wrong rendering or behaviour (games)

17. **d3d12, RTV format ignored**: an `_SRGB` RTV on a UNORM swapchain (the
    standard flip-model pattern) gets the wrong gamma, or Metal rejects the
    pipeline. *Fix:* a format-view texture in `struct mad_rtv`. Fast loop.
18. **d3d12, ExecuteIndirect**:
    - the count buffer is ignored, so stale records are drawn;
    - multi-argument signatures (root constants plus a draw, common in
      GPU-driven engines) are skipped.
    This is relevant to Elden Ring.
19. **d3d12, re-executing a closed list without Reset leaks ring chunks**:
    memory climbs until the app is killed. *Fix:* retire the previous batch's
    slots at replay start. Fast loop.
20. **d3d12, occlusion results into a GPU-only buffer are dropped**: everything
    reads as occluded. Timestamp queries also always resolve to 0.
21. **d3d12, buffer-to-texture copies are not clamped to the destination mip**
    (block-aligned BC footprints): the Metal blit region goes out of bounds.
22. **d3d12, typed-buffer UAV clears use a 32-bit pattern whatever the
    format**: R8, R16 and RGBA32 clears are wrong.
23. **d3d12, swapchain format straight to `CAMetalLayer`**: RGBA8 may not be
    accepted by the layer. Medium confidence, since RGBA8 games already run;
    verify first.
24. **d3d12, Wait-before-Signal stalls 5 s** in the default synchronous mode.
25. **win32u, `QueryDisplayConfig` returns 0 paths** while the buffer-size
    query says 1. Engines that use QDC (Unreal, SDL3) see no display.
26. **win32u, display modes**:
    - a devmode without width and height snaps the game back to native;
    - the native mode disappears from the list after a mode change.
27. **media, WMA**:
    - candidate retries keep the bytes from earlier attempts;
    - EXTENSIBLE input gets the wrong extradata offset;
    - packets whose frames are all rejected skip concealment.
    VideoToolbox restarts on non-keyframes.
28. **audio**:
    - the first client fixes the device format (mono or 44.1 kHz) for the
      whole session;
    - the resampler drops one frame per pass;
    - `qpctime` uses `mach_absolute_time`.
29. **input, game-mode message drain** only runs from `PeekMessage` or
    `GetAsyncKeyState`, so a thread blocked in `GetMessage` gets no input.
30. **controller input**:
    - the button press that closes Madeira's menu reaches the game;
    - stick keys stay held when their binding changes;
    - keyboard/mouse pad mode has no per-key reference count.
31. **crypto, 64-bit `enum_root_certs` consumes the shared root list**, so
    later WoW64 imports see no roots.

### State and data integrity (app)

32. **Steam, a failed "Upload saves and close" wedges the session gate** for
    the rest of the run: downloads never resume, and the cloud check before
    play is off.
33. **Steam, an interrupted update still counts as a full install**, so Play
    starts a mix of old and new files.
34. **Launch, `sessionsThisRun` is counted before a session exists**, so one
    failed start blocks every later one until restart (not verified).
35. **Dock, the sign-in handoff file exists while the game's installers run**.
    Low impact, since guest code shares the process anyway.
36. **Wine, `wine_process_start` failure path** leaves the injected fd and the
    server state stale.

### Lower

These came from the reviewers as lower-impact items:

- **Steam:** manifest varint traps on malformed data; chunk SHA-1 not checked;
  free-space check skipped on resume.
- **d3d12, leaks:** descriptor heap buffers, root-signature sampler tables and
  samplers; the typed-view cache is unbounded.
- **wineserver:** `ios_fd_is_inet` cache staleness.
- **ntdll:** `load_global_options` writes the session-global PEB.
- **d3d12 unix:** AGS rewrite over-read; unused input elements fail pipelines;
  stale converter ID on partial rebuilds.
- **Other:** PrefixExtractor path hardening (the archive is bundled and
  trusted); DualSense trigger effects persist when the controller is replaced.

## Build and CI

None of these were fixed on this branch.

- **Inputs no script produces:**
  - `wine/build-macos` (`config.h` and generated headers);
  - the base `app/Madeira/libwineserver.a`, which `build/wineserver/build.sh`
    patches rather than builds from source (this matters for the LGPL
    source-offer claim);
  - `libdxmt_combined.a` (`build/dxmt-ios/build.sh` only refreshes an existing
    copy);
  - FreeType, which is an unpinned clone.
- **Builds that report success after a failure:**
  - `build/ntdll-unix/build.sh` archives whatever objects are left and exits 0;
  - `gen_gnutls_symtab.sh` can produce an empty symbol table;
  - `ar rcs` into existing archives accumulates stale members.
- **gnutls:** `build/gnutls-ios/build.sh` never checks `SHA256SUMS` and never
  refreshes the tracked archives.
- **BUILDING.md** misses these steps: `stage-licenses.sh`, `madeira-dock`, the
  `dxmt/toolchains` link, Homebrew `llvm-objcopy`, and building the PE side
  before the unix side. It also says `build-pe.sh` installs into the app; it
  doesn't.
- **`gen-config-catalog.py` breaks on Windows**: backslash paths and a CRLF or
  cp1252 encoded output.
- **Host tests have no runner.** Several print PASS when their harness was
  skipped.
- **On Windows with `core.autocrlf=true`,** the hash-pinned converter headers
  fail `SHA256SUMS`. *Fix:* add a `-text` rule in `.gitattributes`.
- **A working GitHub Actions setup exists in the fork Axoled-Student/Madeira**,
  about 400 commits behind upstream. Porting it means fixing the
  missing-input list above first.
